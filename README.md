# Практическая работа №3. Вариант 20

Ассемблер учебной виртуальной машины (УВМ) переводит CSV-программу в
промежуточное представление и формирует бинарный файл. Интерпретатор
выполняет базовые команды и сохраняет дамп памяти в JSON. Для запуска
нужен Python 3.9 или новее. Проект использует стандартную библиотеку.

## Запуск ассемблера

```sh
./run.sh SOURCE OUTPUT [--test | --fields]
./run.sh --help
```

| Аргумент | Назначение |
| --- | --- |
| `SOURCE` | Путь к исходной CSV-программе. |
| `OUTPUT` | Обязательный путь к бинарному результату. Родительский каталог должен существовать. |
| `-t`, `--test` | Напечатать байты в шестнадцатеричном виде после записи файла. |
| `--fields` | Напечатать поля A, B, C и, где применимо, D без записи файла. Демонстрация этапа 1. |
| `-h`, `--help` | Показать справку. |

Обычный запуск записывает файл и печатает его размер в байтах. Режим
`--test` также печатает по одной строке байтов на команду. Режим
`--fields` принимает обязательный `OUTPUT` для совместимости интерфейса
этапа 1. Флаги `--test` и `--fields` взаимоисключающие.

Ассемблер записывает результат во временный файл и после успешной записи
атомарно заменяет выходной файл. Для результата внутри проекта используйте
расширение `.bin` или каталог `output/`. Они исключены из Git.

Код `0` означает успешное выполнение, `1` означает ошибку чтения,
кодировки, содержимого CSV или записи, `2` означает ошибку аргументов.
Диагностика идёт в stderr. Для ошибки CSV или команды указан номер
строки, считая с единицы.

## Синтаксис CSV

Файл в кодировке UTF-8 с необязательной меткой BOM. В каждой записи сначала
указывается мнемоника, затем операнды через запятую. Файл начинается сразу
с команд. Полностью пустые строки пропускаются. Кавычки оформляются по
правилам CSV. После разбора CSV пробелы по краям полей удаляются. Регистр
букв мнемоник и префикса `r` неважен.

Операнды записываются десятичными цифрами от `0` до `9`. Для регистров
допустим префикс `r`, например `r5` или `5`. Адрес регистра и смещение
занимают 5 бит (от 0 до 31). Константа занимает 18 бит (от 0 до 262143).
Операнды указываются в порядке полей B, C, D.

| Запись | A | B | C | D | Семантика УВМ |
| --- | ---: | --- | --- | --- | --- |
| `load,r5,532` | 32 | Целевой регистр | Константа | — | Записать константу в регистр. |
| `read,r25,r22,11` | 62 | Регистр адреса | Целевой регистр | Смещение | Прочитать из памяти по адресу B + D. |
| `write,r10,r23` | 53 | Регистр значения | Регистр адреса | — | Записать значение B по адресу из C. |
| `popcnt,r29,r12` | 36 | Регистр значения | Регистр адреса | — | Записать число единичных битов B по адресу из C. |

В таблице адрес B + D означает сумму значения регистра B и смещения D.

## Формат машинного кода

Каждая команда занимает 5 байт в порядке little-endian. Номера битов
считаются от младшего бита. Все неиспользуемые биты равны нулю.

| Команда | A | B | C | D |
| --- | --- | --- | --- | --- |
| `load` | 0–5 | 6–10 | 11–28 | — |
| `read` | 0–5 | 6–10 | 11–15 | 16–20 |
| `write`, `popcnt` | 0–5 | 6–10 | 11–15 | — |

## Запуск интерпретатора

```sh
python3 -B -m src.interpreter PROGRAM DUMP START END
python3 -B -m src.interpreter --help
```

| Аргумент | Назначение |
| --- | --- |
| `PROGRAM` | Путь к бинарному файлу, созданному ассемблером. |
| `DUMP` | Путь к JSON-дампу. Родительский каталог должен существовать. |
| `START`, `END` | Первый и последний байтовые адреса дампа в десятичной записи. Оба входят в диапазон. |

JSON содержит поля `start`, `end` и массив `memory` с байтами от 0 до 255.
Элемент `memory[i]` показывает содержимое адреса `start + i`. Для дампа
внутри проекта можно использовать расширение `.dump.json` или каталог
`output/`, которые исключены из Git.

Код завершения `0` означает, что дамп сохранён, `1` означает ошибку
чтения, исполнения или записи, `2` означает ошибку аргументов или
диапазона. Интерпретатор обновляет дамп только после успешного исполнения.

## Модель памяти УВМ

- Общая память команд и данных состоит из 262144 байтов с адресами от 0
  до 262143. Объём покрывает все байтовые адреса, задаваемые 18-битной
  константой. Память и 32 регистра `r0`–`r31` изначально обнулены.
  Все регистры, включая `r0`, доступны для записи.
- При загрузке байты программы занимают адреса от 0 до её длины минус 1.
  Счётчик команд начинает с 0. На каждом шаге интерпретатор считывает
  пять байтов из общей памяти, декодирует их и выполняет команду.
  Счётчик продвигается на пять байтов. Исполнение заканчивается,
  когда счётчик достигает длины загруженной программы.
- `load` записывает 18-битную константу C в регистр B. `read` читает
  беззнаковое 32-битное слово с адреса `register[B] + D` в регистр C.
  `write` сохраняет 32-битное значение регистра B по адресу из C.
  Для данных используется little-endian. Смещения выражены в байтах,
  выравнивание слов не требуется. Все четыре байта слова должны
  помещаться в память. Последний допустимый адрес начала слова — 262140.
- Чтение и запись данных используют тот же массив байтов, что и
  выборка команд. Запись в байты будущей инструкции изменит команду,
  которую увидит интерпретатор. В примере массивы размещены за кодом.
- Неизвестные коды и ненулевые резервные биты вызывают ошибку с адресом
  команды. `popcnt` распознаётся, а при попытке её выполнить интерпретатор
  сообщает, что команда будет доступна на этапе 4.

## Демонстрация этапа 3

В `examples/copy_array.csv` первые команды записывают
массив в память. Затем каждая команда `read` читает элемент с очередным
смещением, а `write` сохраняет его в целевой области.

| Область | Байтовые адреса |
| --- | --- |
| Код программы, 31 команда | 0–154 |
| Исходные 5 слов | 256–275 |
| Целевые 5 слов | 288–307 |

```sh
demo_dir=$(mktemp -d)
./run.sh examples/copy_array.csv "$demo_dir/copy.bin"
python3 -B -m src.interpreter "$demo_dir/copy.bin" "$demo_dir/memory.dump.json" 256 307
python3 -B - "$demo_dir/memory.dump.json" <<'PY'
import json
import struct
import sys

with open(sys.argv[1], encoding="utf-8") as stream:
    dump = json.load(stream)

memory = bytes(dump["memory"])
source = struct.unpack_from("<5I", memory, 256 - dump["start"])
destination = struct.unpack_from("<5I", memory, 288 - dump["start"])
assert source == destination == (17, 1024, 0, 262143, 255)
print("Исходный массив", list(source))
print("Копия массива", list(destination))
PY
```

```text
Размер бинарного файла: 155 байт
Исходный массив [17, 1024, 0, 262143, 255]
Копия массива [17, 1024, 0, 262143, 255]
```

## Структура и функции

- `src/assembler.py` задаёт коды операций, разрядности и таблицу команд.
  `OperandSpec` хранит верхнюю границу поля и признак регистра.
  `Instruction` хранит A, B, C и необязательное D в неизменяемом объекте.
  `Instruction.format_fields()` форматирует поля для демонстрации.
  `parse_program(lines)` возвращает список команд в порядке CSV или
  возбуждает `AssemblyError`. `_parse_row(row)` сопоставляет запись с
  таблицей команд, а `_parse_operand(token, field, spec)` проверяет
  формат и диапазон операнда. `encode_instruction(instruction)` проверяет
  поля промежуточной команды и упаковывает её в пять байтов.
  `encode_program(instructions)` собирает байты команд в порядке программы.
  `decode_instruction(code)` проверяет код операции и резервные биты
  и восстанавливает поля команды.
- `src/cli.py` реализует интерфейс программы. `create_parser()` описывает
  пути и флаги. `main(argv)` читает CSV и выбирает режим работы.
  `_print_hex(code)` печатает байты по командам.
- `src/vm.py` реализует память и исполнение. `VirtualMachine(program)`
  загружает код, `run()` выбирает и исполняет команды, `_execute()` применяет
  операцию к регистрам или памяти, а `dump(start, end)` возвращает байты
  диапазона. `validate_range()` проверяет границы дампа, а `_word_slice()`
  проверяет адрес и вычисляет срез 32-битного слова.
- `src/interpreter.py` предоставляет CLI интерпретатора. `create_parser()`
  описывает аргументы, а `main(argv)` читает программу, запускает УВМ и
  сохраняет JSON-дамп.
- `src/file_output.py` выполняет атомарную запись результатов через
  `write_output(source, output, data)`. `_check_destination()` проверяет
  выходной путь и защищает входной файл от перезаписи.
- `run.sh` запускает CLI из любой текущей папки. Относительные пути
  аргументов отсчитываются от текущей папки пользователя.
- `examples/references.csv` содержит эталоны для ассемблера.
  `examples/copy_array.csv` проверяет операции с памятью.
- `tests/` проверяет оба CLI, ассемблирование, декодирование и исполнение.

## Тестирование

```sh
python3 -B -m unittest discover -s tests -v
```

Тесты сверяют поля команд и эталонные байты, проверяют исполнение на
границах памяти, доступ к коду через операции с данными, диагностику
ошибок, содержимое JSON-дампа и точное копирование массива. Отдельный
шаг сборки проекта не требуется.
