# Практическая работа №3. Вариант 20

Ассемблер учебной виртуальной машины (УВМ) переводит CSV-программу во
внутреннее представление. В тестовом режиме он печатает поля каждой команды
в формате из спецификации. Для запуска нужен Python 3.9 или новее.
Проект использует только стандартную библиотеку.

## Запуск

```sh
./run.sh SOURCE OUTPUT [--test]
./run.sh --help
```

| Аргумент | Назначение |
| --- | --- |
| `SOURCE` | Путь к исходной CSV-программе. |
| `OUTPUT` | Обязательный путь для бинарного результата. Запись предусмотрена на этапе 2. |
| `-t`, `--test` | Напечатать поля A, B, C и, где применимо, D. |
| `-h`, `--help` | Показать справку. |

На этапе 1 ассемблер принимает `OUTPUT` и оставляет выходной путь нетронутым.
При успешном запуске без `--test` программа завершится без вывода. Код `0`
означает успешное выполнение, `1` означает ошибку чтения, кодировки или
содержимого CSV, `2` означает ошибку аргументов. Диагностика идёт в stderr.
Для ошибки CSV или команды указан номер строки, считая с единицы.

## Синтаксис CSV

Файл в кодировке UTF-8 с необязательной меткой BOM. В каждой записи сначала
указывается мнемоника, затем операнды через запятую. Файл начинается сразу
с команд. Полностью пустые строки пропускаются. Кавычки оформляются по
правилам CSV. После разбора CSV пробелы по краям полей удаляются. Регистр
букв мнемоник и префикса `r` неважен.

Операнды записываются десятичными цифрами от `0` до `9`. Для регистров
допустим префикс `r`, например `r5` или `5`. Адрес регистра и смещение
занимают 5 бит (от 0 до 31). Константа занимает 18 бит (от 0 до 262143).
Операнды указываются в порядке полей B, C, D.

| Запись | A | B | C | D | Семантика УВМ |
| --- | ---: | --- | --- | --- | --- |
| `load,r5,532` | 32 | Целевой регистр | Константа | — | Записать константу в регистр. |
| `read,r25,r22,11` | 62 | Регистр адреса | Целевой регистр | Смещение | Прочитать из памяти по адресу B + D. |
| `write,r10,r23` | 53 | Регистр значения | Регистр адреса | — | Записать значение B по адресу из C. |
| `popcnt,r29,r12` | 36 | Регистр значения | Регистр адреса | — | Записать число единичных битов B по адресу из C. |

В таблице адрес B + D означает сумму значения регистра B и смещения D.
В памяти и регистрах на этом этапе операции не выполняются.

## Демонстрация

```sh
./run.sh examples/references.csv /tmp/praktika-3.bin --test
```

```text
A=32, B=5, C=532
A=62, B=25, C=22, D=11
A=53, B=10, C=23
A=36, B=29, C=12
```

Четыре строки соответствуют эталонным полям варианта 20. Поле D присутствует
только в команде чтения, в том числе при нулевом смещении.

Пример ошибки с выходом смещения за диапазон

```sh
demo_dir=$(mktemp -d)
printf 'read,r1,r2,32\n' > "$demo_dir/invalid.csv"
./run.sh "$demo_dir/invalid.csv" "$demo_dir/result.bin" --test
echo "$?"
rm "$demo_dir/invalid.csv"
rmdir "$demo_dir"
```

```text
Ошибка: …/invalid.csv: строка 1: поле D: допустимо от 0 до 31
1
```

## Структура и функции

- `src/assembler.py` задаёт коды операций, разрядности и таблицу команд.
  `OperandSpec` хранит верхнюю границу поля и признак регистра.
  `Instruction` хранит A, B, C и необязательное D в неизменяемом объекте.
  `Instruction.format_fields()` форматирует поля для демонстрации.
  `parse_program(lines)` возвращает список команд в порядке CSV или
  возбуждает `AssemblyError`. `_parse_row(row)` сопоставляет запись с
  таблицей команд, а `_parse_operand(token, field, spec)` проверяет
  формат и диапазон операнда.
- `src/cli.py` реализует интерфейс программы. `create_parser()` описывает
  пути и флаги. `main(argv)` открывает CSV, вызывает транслятор, выводит
  диагностику или поля команд и возвращает код завершения.
- `run.sh` запускает CLI из любой текущей папки. Относительные пути
  аргументов отсчитываются от текущей папки пользователя.
- `examples/references.csv` содержит все четыре эталонные команды.
- `tests/` проверяет транслятор и интерфейс командной строки.
  `run_cli()` запускает скрипт в отдельном процессе, а `setUp()`
  подготавливает временные пути для тестов CLI.

## Тестирование

```sh
python3 -B -m unittest discover -s tests -v
```

Тесты сравнивают все четыре эталона, проверяют границы полей, ошибки
синтаксиса, кодировку CSV, аргументы, коды выхода и сохранность выходного
файла. Отдельный шаг сборки для этапа 1 не требуется.
